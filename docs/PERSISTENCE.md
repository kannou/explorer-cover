# 作業状態の保存・復元（6b）

## 使い方

`run.cmd`で通常起動すると前回の作業状態を復元する。保存対象の変更後に約1秒待って連続する変更をまとめ、内容が変わった場合だけ保存する。未変更時はスナップショット・JSONを生成しない。初回と終了時にも状態を取得し、終了時は最後の状態の保存完了を待つ。

保存先は`%LOCALAPPDATA%\explorer-cover\workspace.json`。ショートカット・マウス・QuickLookの設定とは別ファイルで、形式に`version: 1`を付ける。

保存する項目:

- 左右それぞれのタブ順、各タブの場所、選択中のタブ
- アクティブなペイン
- ウィンドウの通常時の位置・サイズと最大化状態
- 左右ペインの幅比率、サイドビュー幅
- ブックマークの名前・パス・順序。全件削除した空の一覧も復元する

パス欄で編集中の文字列は保存せず、最後に成功した場所を使う。復元先へ一度も移動できなかったタブは、元の保存パスを保持する。戻る／進むの履歴、ファイル一覧内の選択とスクロールは今回の再起動復元対象に含めない。

## 復元時の挙動

存在確認をせずに状態モデルとタブ見出しを復元し、左右の選択中タブだけを最初に読み込む。非選択タブは初めて選んだときにShellビューを生成する。その後はこれまでどおり、タブ切替時にビューを保持する。

WSLや削除済みフォルダーへ到達できなくても、タブとブックマークは削除しない。パス欄の矢印で再試行するか、別の場所を入力して移動できる。WSLの確認・タイムアウトは6a-3の非同期処理を利用する。

## 保存の保護とエラー

- 同じディレクトリに一時ファイルを書き、ディスクへフラッシュしてから原子的に置換する。前回の本体は`workspace.json.bak`へ保存する。置換に失敗した場合は前の本体を維持し、一時ファイルを削除する。
- 本体のJSONや項目が不正なら、元のファイルを`workspace.json.invalid-<ID>`へ退避し、正常なバックアップがあれば復元する。バックアップも読めなければ初期状態で起動する。画面上部に回復内容を表示する。
- 未対応バージョンや読み取り権限不足の場合は元データを上書きせず、その起動では保存を無効にして通知する。
- `workspace.json.lock`を排他的に開き、同じ保存先を複数ウィンドウで上書きしない。保存先を使用中の2つ目のウィンドウは初期状態で開き、保存しない旨を表示する。最初のウィンドウを閉じた後に再起動すると通常の復元・保存へ戻る。
- 自動保存に失敗した場合は画面下部に通知し、後で再試行する。終了時にも失敗した場合は「保存せずに終了する」か「終了を取り消す」を選べる。
- 強制終了・電源断直前の未保存変更までは保証しない。通常終了では保存完了を待つ。

## 試用と検証用の起動

`trial.cmd`およびパスを明示した起動は一時セッションとし、通常の作業状態を読み書きしない。タイトルにも一時セッションと表示する。保存・復元の試用には`run.cmd`を使う。

```powershell
# パス指定は一時セッション
.\run.ps1 -LeftPath 'D:\作業' -RightPath 'D:\資料'

# 専用の保存先を指定して独立した作業状態を試す
$env:EXPLORER_COVER_STATE = 'D:\検証\workspace.json'
.\run.ps1
```

`EXPLORER_COVER_STATE`を明示した場合は、その保存先を使う。パス引数も指定した場合は引数を初期状態とし、指定保存先へ保存する。

## 変更時だけ行う保存準備

2026-09-23、性能改善の順番2として、毎秒の全状態取得を変更通知に基づく処理へ置き換えた。

- `WorkspaceChangeTracker`で移動成功、タブ追加・削除・順序・選択、アクティブペイン、幅、ブックマーク追加・削除・改名を監視する。未確定のパス入力や移動エラーは保存を予約しない。追加項目の監視を開始し、削除・終了時には購読を解除する。
- `WorkspacePersistence`でウィンドウの位置・サイズ・表示状態の変化を監視する。位置だけの移動も保存対象にし、最小化前の通常表示／最大化の区別を維持する。WPFの[LocationChanged](https://learn.microsoft.com/en-us/dotnet/api/system.windows.window.locationchanged?view=windowsdesktop-10.0)と[StateChanged](https://learn.microsoft.com/en-us/dotnet/api/system.windows.window.statechanged?view=windowsdesktop-10.0)を利用する。
- `WorkspaceSaveScheduler`で約1秒の待機を置き、連続する変更をまとめる。保存済みならタイマーを停止する。スナップショット・JSON生成はUIスレッド、ファイル保存は作業スレッドで行う。前回成功時と同じJSONは書き込まない。
- 世代番号で取得時点と現在の状態を区別し、書き込み中の変更を次の保存に残す。取得・保存の失敗時も未保存のまま残し、追加操作がなくても約1秒後に再試行する。成功後は警告を消す。
- 終了時は実行中の保存を待ち、変更通知の有無にかかわらずウィンドウ配置を含めて再取得する。最終保存中に来た変更も保存し、終了取消後は自動保存を再開する。JSONの形式、原子的な置換、バックアップは従来どおり。

## ウィンドウの位置・サイズ（追加）

通常表示時の矩形と最大化状態を保存する。最大化中も通常表示へ戻したときの矩形を保持する。最小化は復元せず、最小化前の通常表示または最大化で起動する。

`window`は任意項目として追加し、既存のバージョン1のJSONはそのまま読める。位置情報がない場合は既定の位置・サイズを使う。保存は物理ピクセルの画面座標とし、Windowsの作業領域座標との変換を行う。復元時は保存矩形に最も近いモニターの作業領域へ位置・サイズを補正する。

`scripts/Verify-WindowLayout.ps1`で旧形式、通常サイズ・位置、最大化後の通常矩形、最小化前の表示状態、画面外・過大サイズの補正を再起動して確認した。記録: `artifacts/window-layout-dd4e3451ba384a3986847f073edb4c73/`。負座標のモニターと作業領域の計算はCoreテストで確認した。実機でのモニター着脱と異なるDPI間の移動は未検証。

参照: [WINDOWPLACEMENTの座標系](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-windowplacement)、[SetWindowPlacement](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowplacement)。

### 異なるDPIのモニターで起動するたびに拡大する不具合の修正

2026-09-21の追加報告を受け、設定画面追加前の`bd829d1`を隔離して検証した。実行ファイルから起動すると、別モニター上の保存幅が1600→2000→2500→3125と増加することを確認した。設定・ショートカットの実装による回帰ではなく、ウィンドウ配置保存の導入時からの不具合だった。設定関連の変更を`a4815f8`へコミットした後、別の変更として修正した。

モニターを移動する最初の配置時にDPIの調整が入り、保存した物理矩形が拡縮されていた。WPFのLoadedで移動先へ配置し、移動先のDPIが適用された後に同じ物理矩形を確定する。最大化も通常矩形の確定後に行い、通常表示に戻す際の拡大を防ぐ。

従来の検証はDLLをdotnet経由で起動しており、実行ファイルに埋め込まれたPerMonitorV2のマニフェストが適用されず、この不具合を検出できなかった。`Verify-WindowLayout.ps1`をrun.cmdと同じ実行ファイルからの起動へ変更し、検証側の座標取得もPer-Monitor DPIに統一した。

修正後のReleaseビルドは警告・エラーなし。接続中の2モニターそれぞれで、起動直後に終了する操作を4回繰り返してサイズ・位置が不変であること、最大化後の再起動と通常矩形への復帰を確認した。通常・最小化・旧形式・画面外補正の既存検証も成功。記録: `artifacts/window-layout-408f8174c8f944c5b58b36bf0cae6f7d`。モニターの物理的な着脱は未検証。

既に拡大したサイズが保存されている場合、元の希望サイズを推定して自動縮小はしない。修正版で一度希望のサイズ・位置へ調整して終了すると、その矩形を維持する。

### Windowsのスナップ配置への対応

通常表示時の保存元を`WINDOWPLACEMENT.NormalPosition`から現在の外枠の矩形へ変更した。スナップ配置では通常表示の復帰先と現在の配置が異なるため、配置前の矩形を保存しないようにする。最大化・最小化中は引き続き通常表示への復帰先を使う。

取得には画面座標を返す[GetWindowRect](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getwindowrect)を使い、作業領域座標からの変換を重ねない。保存するのは位置・サイズであり、Windowsのスナップグループ所属は復元しない。既存の画面外補正と最小サイズ制約は維持する。
