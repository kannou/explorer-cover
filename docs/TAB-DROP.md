# タブへのファイルドロップ

実装・検証日: 2026-09-30

## 操作

ファイル・フォルダーをタブの見出しへドロップすると、そのタブのフォルダーへコピー・移動します。左右どちらのペインでも、非選択タブを宛先にできます。ドロップのためにタブを選択する必要はありません。

| 操作 | 結果 |
|---|---|
| Ctrlを押してドロップ | コピー |
| Shiftを押してドロップ | 移動 |
| 修飾キーなし | Windows Shellが判定。同一ボリューム内の通常のファイルは移動 |
| Escape、バー外へ移動 | ドロップを取り消す |

受け入れ可能な見出しを青枠で示します。見出しが多い場合は、ファイルを持ったままバー端へ移動すると横スクロールします。バーの空白部分、スクロールバー、＋や×のボタンはドロップ先ではありません。

宛先はタブが表示している現在地です。パス欄に入力中の文字列は使用しません。復元後にまだ開いていないタブは保存された初期パスを使用します。タブの選択、並び順、履歴、一覧の表示状態を切り替える処理は行いません。

## Shellへの委譲とエラー

大容量コピー中の操作とアプリ終了時の扱いは、[大容量コピー中の操作と終了](FILE-OPERATIONS.md)を参照してください。

ファイル操作は、宛先フォルダーのWindows Shellドロップ処理へ委譲します。WPFで受け取った元のデータオブジェクト、修飾キー、画面座標、ドラッグ元が許可した操作を渡し、Shellから返された結果をドラッグ元へ返します。Windows標準の判定は[IDropTargetの説明](https://learn.microsoft.com/en-us/windows/win32/api/oleidl/nf-oleidl-idroptarget-drop)に従います。

WSLが関わる通常ファイル・フォルダーのコピーでは、コピー元のパス一覧と宛先を確定し、別のSTAで`IFileOperation`を実行します。コピーの受理を返してUIの停止を防ぎ、標準の進捗・同名確認・取消を利用します。移動や右ボタンドラッグは従来のShellドロップに委譲します。対応範囲と検証結果は[大容量コピー中の操作と終了](FILE-OPERATIONS.md#wslのタブドロップ)を参照してください。

ファイルシステムのフォルダーだけを宛先として受け付けます。宛先が削除済み・ファイル・仮想フォルダーの場合や、Shellの呼び出しが失敗した場合は受け付けず、ペイン下部に「ドロップできません: …」を表示します。Shellがそのデータを受け付けない場合は、コピー・移動を実行しません。

タブの閉鎖、ドラッグ終了・取消、画面の破棄でドロップ先を解放します。見出しの並べ替えは従来のマウスキャプチャで処理し、ファイルのドロップと区別します。

## 検証

`tests/ExplorerCover.TabDrop.Tests`はマウス・キー入力を使わず、不可視のウィンドウでWPFのイベントと座標変換を確認します。ファイル操作は`artifacts/tab-drop-<ID>/`に作成した専用データだけを使用します。

- 20/20成功。非選択タブ、現在地と入力中パスの区別、宛先変更、空白・バー外、Ctrl・Shift・許可効果の伝達、取消、タブ閉鎖・破棄、失敗表示、強調表示、端スクロール、WSLコピーの先行受理と宛先保持を確認しました。
- Shell形式のデータオブジェクトをWPF経由で受け取り、非選択タブへの実コピーと内容保持を確認しました。
- 複数ファイルの実コピー・実移動、日本語名、修飾キーなしの同一ボリューム移動、フォルダーと内容のコピー、取消時の元ファイル保持、文字列データと無効な宛先の拒否を確認しました。
- Core 47/47、Sidebar 10/10、Persistence 10/10成功。Releaseビルドは警告0・エラー0でした。

```powershell
$env:DOTNET_CLI_HOME = "$PWD\.tools\cli"
.\.tools\dotnet\dotnet.exe run --project tests\ExplorerCover.TabDrop.Tests -c Release
```

アプリ内の一覧からローカルとWSLのタブへの大容量コピー、およびWSLの同名確認中の操作・取消を実画面で確認しました。外部Explorerからのドラッグ、右ボタンドラッグ、WSL以外のUNC・クラウド、異なるDPI環境は未検証です。実画面をマウス・キーで操作する検証は、利用者の許可を得て実施します。
