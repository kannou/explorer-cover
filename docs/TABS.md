# タブと移動（段階5b）

実装・検証日: 2026-09-20

この文書は段階5bの記録です。追加した段階5b-2のマウス操作と実画面検証の結果については[別の記録](TAB-MOUSE.md)を参照してください。

## 実装範囲

左右のペインに独立したタブを追加しました。追加・切替・閉じる・複製、戻る・進む・親へ移動を段階5aの共通コマンドに接続し、JSONによるキー変更にも対応しています。キーと起動方法は[README](../README.md)を参照してください。

- 新規タブはペインの起動時の場所を開きます。最初のタブを閉じても、この初期移動先は変わりません。
- 複製は選択中タブの現在地を開きます。履歴・選択・スクロール位置を複製元からコピーしません。
- タブ切替は両方向に循環します。閉じたときは右隣、右端なら左隣を選択します。最後の1タブは残します。
- 戻る・進む・親へ移動できない場合や、移動要求の処理中は該当ボタンを無効にします。
- 作業状態の保存、タブの並べ替え、閉じたタブの復元、マウスのサイドボタンの割り当ては今回の範囲に含みません。

## ビューと履歴の管理

`BrowserPane`はタブごとに`ExplorerHost`と`TabNavigation`を保持します。タブを切り替えるときはビューの表示・非表示だけを変更し、一覧の選択とスクロール位置を保持します。タブを閉じるとそのビューを破棄し、終了時には残ったビューをすべて解放します。閉じたタブや非選択タブからの遅延通知で、別のタブの現在地を変更しない構成です。移動完了でフォーカスを戻す処理も、対象タブと操作対象ペインを確認します。

履歴の管理主体はアプリです。シェルのtravel logの更新を`EBO_NOTRAVELLOG`で止めています。[Microsoftのオプション定義](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/ne-shobjidl_core-explorer_browser_options)

`TabNavigation`が戻る・進むの要求先を保持し、シェルから成功した現在地が届いた時点で`NavigationHistory`のカーソルを確定します。失敗時は要求だけを取り消し、現在地と履歴を維持します。想定先とは別の場所へリダイレクトされた場合は、その実際の場所を通常の移動として記録します。A→B→戻る→CではBへの進む履歴を破棄します。一覧内でフォルダーを開いた場合も同じ成功通知で履歴を更新します。

保持方式は選択・スクロールの維持を優先して採用しました。このPCでの1回の測定では、プロセスのワーキングセットは2タブで162.8 MiB、移動操作後の5タブで231.5 MiBでした。タブだけの増分を分離した測定ではなく、上限や長時間利用時の値を保証するものではありません。多数のタブを長時間開く使い方で負担が大きければ、試用後に非選択ビューの休止を検討します。

### 検証時に判明した環境要因

- このPCのAutoHotkeyが左Ctrl+Tabをウィンドウ切替に置き換えており、初回のタブ切替テストでアプリにキーが届きませんでした。常駐設定を変更せず、右Ctrlで標準のCtrl+Tab／Ctrl+Shift+Tabを検証しました。実際の利用ではJSONで別キーを選ぶこともできます。
- Windows PowerShell 5で認識されない検証コードの`ushort`型名を`uint16`に修正しました。検証スクリプトのUTF-8 BOMを維持しています。
- コピー検証の繰り返しで新しいファイルが一覧の表示範囲外になる問題を避けるため、検証ファイル名を先頭に並ぶ形式にし、更新と先頭への移動を追加しました。
